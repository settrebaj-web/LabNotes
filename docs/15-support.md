## А бөлімі. Өтініштермен жұмыс

**Issue tracker:** GitHub Issues + шаблондар (`.github/ISSUE_TEMPLATE/`: bug, feature, question).
Белгілер (Issues → Labels → New label): `bug`, `enhancement`, `question`, `triage`, `P0`, `P1`, `P2`, `P3`.

## Б бөлімі. Қолдау саясаты (Support Policy) — LabNotes

**Құжат нұсқасы 1.0, күні: 2026-11-24. Жауапты: Торебай Ә.Е.**

### 1. Минималды ОС нұсқасы (minSdk)
- Қазір: **minSdk 26 (Android 8.0)** — Android Studio статистикасы бойынша белсенді құрылғылардың ~97 %-ын қамтиды.
- **Көтеру ережесі:** егер нұсқаның үлесі біздің аудиторияда (Play Console → Statistics → Android version) < 3 % болса
  **және** оны ұстау құны жоғары болса (кітапхана талап етеді, қауіпсіздік API жоқ) — жылына ең көбі бір рет көтереміз.
- **Тәртібі:** (1) 60 күн бұрын CHANGELOG пен «Что нового»-да хабарлау; (2) ескі minSdk бар соңғы нұсқа
  **LTS** ретінде белгіленеді; (3) minSdk көтерілген нұсқа — **MINOR** (кейбір пайдаланушылар жаңарту алмаса — MAJOR).
  Ескі құрылғыдағы пайдаланушылар соңғы үйлесімді нұсқада қалады (Play оларға соны береді).

### 5. Инциденттер мен осалдықтарға әрекет ету жоспары
**Инцидент** = P0 критерийі (crash-free < 99 %, деректер жоғалуы, қауіпсіздік, ANR > 0.47 %).
1. **Анықтау** (≤ 15 мин): Crashlytics/Vitals ескертулері, пікірлер, issue.
2. **Бағалау** (≤ 30 мин): қай нұсқа, қанша пайдаланушы, қайталау; issue `P0` + `incident`.
3. **Шектеу** (≤ 1 сағ): Halt rollout; Remote Config kill switch; қажет болса сервер жағынан шектеу.
4. **Түзету** (≤ 24 сағ): hotfix PATCH → internal → staged rollout (тез: 10 % → 100 %).
5. **Хабарлау:** дүкендегі «Что нового», пікірлерге жауап; деректер ағып кетсе — пайдаланушыларға және заң талап еткен органдарға.
6. **Postmortem** (≤ 5 күн): хронология, MTTD/MTTR, түпкі себеп, кінәсіз талдау, қайталамау шаралары (тест, alert).

**Осалдықтар:** хабарлау арнасы — e-mail (privacy-policy беті) және GitHub *Security → Report a vulnerability* (private).
Жауап — 48 сағатта; critical/high — 7 күнде түзету, medium — келесі релизде; түзету шыққанға дейін ақпарат жарияланбайды
(responsible disclosure). Keystore немесе API кілті ағып кетсе: кілттерді ауыстыру (upload key reset, Firebase API key restriction),
git тарихынан тазарту (`git filter-repo`), CI secrets жаңарту.
